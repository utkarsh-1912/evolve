## 2. Architecture
- **npm workspaces monorepo**: `packages/ui` (design system: tokens, primitives, patterns), `apps/citizen`, `apps/counselor`. Next.js `transpilePackages: ["@evolve/ui"]`.
- **Primitives**: Radix UI (Dialog, DropdownMenu, Tabs, Tooltip, Toast, Popover, Switch, Accordion) for accessibility. Icons: `lucide-react`. Variants: `class-variance-authority` + `clsx` + `tailwind-merge`. Tables: `@tanstack/react-table`. No other UI kits (no MUI/Chakra/shadcn copy-paste of unrelated styles; shadcn-style local components built on Radix are fine).
- **Living style guide**: route `/design-system` in each app renders every component in every state, EN + AR, light + Ledger. It doubles as the visual-regression target (Playwright `toHaveScreenshot`). No Storybook (keeps deps lean).
- **Data**: typed API client generated by hand from contracts/api.md; React Query (`@tanstack/react-query`) for caching, retries and loading state; the mock adapter stays (SIMULATED) behind the same interface.

## 3. App shells
**Citizen shell** (Clinic theme)
- Desktop: left sidebar 264 px (logo; nav: Home, My results, Compatibility, Care plan, Family, Privacy & sharing, Help), top bar (page title + breadcrumb, language switch, notifications bell with count, profile menu).
- Mobile (<768): top bar + bottom tab bar (Home, Results, Compatibility, Care, More).
- **Context strip** under the top bar: signed-in person, couple status (Not linked / Invitation sent / Both consented / Result ready), consent status chip with expiry. Always visible.
- Footer inside the shell: compliance line (decision support · not a diagnosis · certificate issued regardless) + environment.

**Counselor shell** (Ledger theme, dark, density "comfortable/compact" toggle)
- Left rail: Queue, Cases, Calendar (SIMULATED), Reports; top bar with global search (case ID only, no gene search across patients), shift status (online_access scope: "On shift" toggle), profile.
- Split view: list ↔ detail, resizable.

## 4. Surfaces
### 4.1 Citizen
1. **Home dashboard**: greeting; "Your next step" hero card (one primary action, chosen by loop state); status cards (Results, Compatibility, Care plan); recent activity (from audit, own events only).
2. **My results**: FindingCard list grouped by "Needs a conversation" / "For your information"; a detail drawer with plain explanation, technical details (gene, HGVS, classification), confirmatory test recommendation (if `confirmatory_recommended`), and "Who can see this" chip (Only you / You and your counselor).
3. **Compatibility**: 3-step wizard (Invite → Both consent → Private check) with a stepper; the result page uses the two-column layout: result (left, primary), "Sharing & consent" panel (right: who consented, when, expires, withdraw).
4. **Result detail / explainer**: big locked number, comparison, DetectionBar, provenance drawer, "Talk it through" CTA, questions notebook.
5. **Teach-back**: 3–4 question check, one question per screen, progress, kind feedback, never "fail" wording; failure routes to a counselor (escalation (d)).
6. **Care plan**: CareTimeline (7 states), appointments (SIMULATED booking), tasks (confirmatory test), CareNavigator options as equal-weight cards, Thiqa eligibility checklist (P3 backend).
7. **Family**: create a Cascade Screening Token → QR + share sheet; explains what is and isn't shared.
8. **Privacy & sharing**: consents table (status, scope, expiry, revoke with confirm), audit trail table ("who saw what, when"), download my data (SIMULATED).
9. **Notifications**: inbox list; each item links to its surface.
10. **Help**: glossary (carrier, recessive, residual risk), contact counselor, the "Seven promises".
11. **SURE check** after counseling (4 items) — on the care plan.

### 4.2 Counselor workbench (`apps/counselor`)
1. **Queue**: TanStack table, columns: Case, Trigger (a/b/c/d chip), Priority, Age (SLA timer vs 48 h), Couple status, Assigned to; filters, saved views, keyboard navigation (j/k, Enter).
2. **Case view**: header (case ID, trigger, SLA), tabs: Brief (Consultation Brief), Pedigree (GA4GH graph render: SVG, consanguinity loops marked, F shown as genome-wide context), Variants (consented scope only, with "outside consent" placeholders that say nothing), Tasks (FHIR Tasks, create/complete), Notes, Timeline (loop states + audit).
3. **Actions**: advance loop state, record SURE outcome, **document human closure** (counselor-only, confirm dialog), schedule (SIMULATED).
4. Every screen shows the access basis: "Viewing under: couple consent ✔ · on shift ✔".

## 5. Design-system rules
- **Tokens** (CSS variables, already in design/tokens.css → move to `packages/ui/tokens`): color (brand, neutral 50–950, signal, surface levels 0–3), spacing 4/8/12/16/24/32/48/64, radius 6/10/16/24, elevation 0–3, type scale (12/14/16/18/20/24/30/36/48/60/72), motion durations 120/200/320 ms + standard easing.
- **Typography**: Lexend for display ≥30 px only; Instrument Sans for UI; JetBrains Mono for IDs, digests, codes; IBM Plex Sans Arabic for AR. Body 16 px, line-height 1.5; max line length 72ch.
- **Components** (all in packages/ui, each with all states): Button (primary/secondary/ghost/danger; sizes sm/md/lg; loading), IconButton, ChamferCTA (marketing only), Input/Textarea/Select/Checkbox/Radio/Switch with label, help and error, FormField, Card (flat/raised), StatCard, Badge/StatusChip, VisibilityChip ("Only you"…), Alert (info/success/warning/danger), Toast, Dialog, ConfirmDialog, Drawer, Tabs, Stepper, Accordion, Tooltip, DropdownMenu, Avatar, EmptyState, Skeleton, ErrorState, DataTable, Pagination, Timeline, Breadcrumbs, AppShell, Sidebar, BottomTabs, TopBar, ContextStrip, NotificationBell, LangSwitch, LockedNumber, SourceCaption, DetectionBar, IconArray, OverlapCircles, SunburstProgress, PedigreeGraph, AuditTable, ConsentTable, FindingCard, CareTimeline.
- **Content design**: sentence case; condition names before gene symbols; no jargon without a glossary tooltip; non-directive verbs ("you can", "some people choose"); numbers only via LockedNumber; Arabic strings reviewed (TODO(native-review)).
- **Iconography**: lucide, 1.5 px stroke, 16/20/24.

## 6. State matrix (required for every data view)
Loading (skeleton matching the layout, no spinners for >300 ms waits) · Empty (illustration-free EmptyState with one action) · Error (ErrorState with retry + reference ID, no PHI) · Offline (banner) · Permission denied (explains the consent needed) · Stale (data older than session → "Refresh") · Partial (gate-blocked message → GuardBanner "Held for counselor review").

## 7. Quality bars (CI-enforced in P3)
- WCAG 2.2 AA: axe 0 serious on every route (EN + AR), keyboard-complete, visible focus ring (lime on navy, navy on light), 44 px targets, reduced motion.
- Visual regression: Playwright screenshots of `/design-system` + 10 key routes × EN/AR × 360/1280.
- Performance: Lighthouse mobile ≥ 90 perf / 100 a11y / ≥ 95 best practices on Home and Results; JS per route ≤ 180 kB gz; LCP ≤ 2.5 s on mid-tier mobile emulation.
- Type-safe: `tsc --noEmit` strict, eslint clean, no `any` in packages/ui.
- Security headers in next.config (CSP without unsafe-inline scripts where feasible, frame-ancestors none, referrer-policy), no PHI in URLs (P-11), no analytics.
- i18n: 0 missing keys in EN; AR keys present (placeholder allowed, flagged); RTL mirrored screenshots.

## 8. Out of scope (guardrail G-02 still applies)
No new product features beyond the charter (no chat with other users, no social sharing, no payments, no marketing CMS). "Enterprise" means quality, consistency and completeness of the charter's surfaces, not more features.

## 10. Clean-UI pass (user direction 2026-11-15 — "our motto is clean UI"; DECISIONS #52)
**Logo:** use the new cropped assets in `design/brand/` — `evolve-logo-transparent.png` (full lockup, transparent, for navy/dark surfaces), `evolve-mark-transparent.png` (icon only: collapsed rail, favicon, mobile top bar), `evolve-logo-navy-cropped.png` / `evolve-mark-navy.png` (tight navy tiles). Never the old 500×500 square. A navy-ink variant for light surfaces is still TODO(team) — until then the logo sits only on navy/dark surfaces.

**Chrome rules**
1. Sidebar → **collapsible icon rail**: default collapsed (72 px, mark + icons) on ≤1440 px, expanded (240 px) on wider; toggle remembered per viewer (localStorage in try/catch). Every icon has a Radix Tooltip (hover + keyboard focus) and an `aria-label`; active item keeps a lime indicator.
2. Top bar → icons only for secondary controls: language (globe), notifications (bell + count), profile (avatar menu), density/theme (counselor). Page title stays as text; drop breadcrumbs where they repeat the title.
3. Context strip → compact chips (icon + 1–2 words), full detail in the tooltip (e.g. shield icon "Consent active" → tooltip "Active until 10 Nov 2026, 09:30").
4. SIMULATED → one global environment banner (text, required) + at most one small flask-icon badge per surface with a tooltip; remove the rest.
5. Secondary actions (copy, expand, filter, download, info) → IconButton + tooltip. **Primary actions keep text** (Check compatibility, Document human closure, Withdraw consent).
6. Copy diet: one-sentence page intros, no repeated explanations; long explanations move into an info-icon popover or the Help glossary.

**Never icon-only (guardrails P-14, P-19, P-16, P-07):** the environment banner, the "decision support · not a diagnosis · certificate issued regardless" line, the certificate statement on results, consent/withdraw controls, escalation/counselor-handoff notices, risk numbers and their "how it was counted" entry. Tooltips are supplementary — nothing needed to understand a result may live only in a tooltip.

**Quality bars unchanged** (axe 0 serious incl. tooltip/focus checks, keyboard-complete, RTL mirrored icons where directional, visual baselines refreshed only for intentional changes).
